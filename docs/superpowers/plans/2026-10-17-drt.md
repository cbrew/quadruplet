# DRT Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** DRT grammars in quadruplet: a `%semantics drt` declaration, DRS
terms with merge, `fol()`, anaphora resolution, multi-sentence discourse,
and scope ambiguity from a storage-style DRT grammar, reproducing the
NLTK book's chapter 10 section 5 examples.

**Architecture:** Option A of the spec. Boxes are new nodes in the sealed
`Lambda` family. A box's referents are de Bruijn binders in the `QVar`
numbering. Merge (`+`) is not a node: the reader turns `K1 + K2` into a box
whose last condition is `K2`, and the box factory flattens box-valued
conditions. So dynamic binding and accessibility are both ordinary scope.
The declaration switches the island lexer (via a predicate) so that `[`,
`]` and `+` are DRT punctuation.

**Tech Stack:** Kotlin 2.4.21 on JDK 25, ANTLR 4.13.2 (Java target,
lexer predicates and actions in Java), Maven via `devenv shell -- mvn -B test`.

**Spec:** `docs/superpowers/specs/2026-10-17-drt-design.md`

## Global Constraints

- Code style per CLAUDE.md: 4-space indent, KDoc on public API, functional style, immutable data.
- All existing tests' assertions still pass; the MASC grammar and the chart (`Chart.kt`, `FeatureGrammar.kt`) are untouched.
- A grammar without `%semantics drt` lexes, parses and reduces exactly as now.
- Nested feature maps are not used; tuples of tuples are fine.
- Terms stay immutable with cached hash and de Bruijn facts (`ground`, `freeVarDepth`, `freeQVarDepth`, `hasBox`); unchanged subterms are shared.
- The Go port (`go/`) is not changed.
- Out of scope: provers (book items 12, 14), Glue/Malt (15), `draw()` (3), gender/number filtering.
- Run everything with `devenv shell -- mvn -B test` (plain `mvn` is not on the host path).

## Decisions this plan makes (the spec left them to the builder)

- **Node names:** `Drs(refs: Int, conds: List<Lambda>)`, `DrsImp(refs: Int, antecedent: List<Lambda>, consequent: Lambda)`, `Resolved(pronoun: Lambda, antecedents: List<Lambda>)`, all in `Unifiable.kt`.
- **No merge node.** The reader rewrites `K1 + K2`: if `K1` reads as a box `([r], [c])`, the result is `([r], [c..., K2])`; otherwise it is `([], [K1, K2])`. `K1 -> K2` with a box antecedent `([r], [c])` becomes `DrsImp(r, c, K2)`, with `r` in scope over `c` and `K2`. **Consequence:** book item 5's unsimplified print `(([x],[walk(x)]) + ([y],[run(y)]))` has no counterpart, because quadruplet merges on reading. The test asserts the merged form only.
- **Index layout.** In `Drs(k, conds)`, `QVar(1)` is the last-listed referent and `QVar(k)` the first, exactly as `k` nested `Exists` would number them. So `fol()` is `k` applications of `createExistential`, and `pretty()` names referents `x(q+1)…x(q+k)` in listed order.
- **Flattening rule.** A condition that is itself a `Drs(j, cs)` is spliced in place. Its `cs` keep their indices, and the `j` new referents are appended after the existing ones (they become the innermost). Every *other* condition of the enclosing box, and the `consequent` of a `DrsImp`, gets `qshift(·, j)`.
- **Declaration:** a token `%semantics <name>`, first in the file. `drt` sets the lexer flag, `logic` or no declaration means logic, and anything else is an error.
- **Candidate order:** referents in scope, outermost box first, then listed order within a box.
- **`fol()` of `Resolved`:** a disjunction of equalities, `createOr(antecedents.map { createEquiv(pronoun, it) })`.
- **Unused referents** are never dropped from boxes; `fol()` drops them through `createExistential`.
- **Double negation:** `createNegation` leaves `¬¬K` alone when `K` is a `Drs`, because DRT double negation blocks accessibility. Logic terms are unaffected.

## Review Focus

- A logic grammar whose `<...>` constants contain `[`, `]` or `+` lexes exactly as before. Test: `testLogicConstantsKeepBrackets`, Task 2.
- `%semantics` with an unknown name fails with a clear message rather than silently meaning logic. Test: `testUnknownSemanticsRejected`, Task 2.
- A box with no conditions, or no referents, translates without crashing: `fol(([], []))` is `true` and `fol(([x], []))` is `true`. Test: `testFolOfEmptyBoxes`, Task 3.
- A pronoun inside a negated or implication box sees outer referents, and a referent inside a negation is invisible outside it. Tests: `testPronounInsideNegationSeesOuter` and `testReferentInsideNegationInaccessible`, Task 4.
- A one-sentence discourse whose only noun phrase is a pronoun (`He runs .`) gives no reading rather than throwing. Test: `testLonePronounHasNoReading`, Task 5.

- [ ] **Step 4: Add `createDrs` and `createDrsImp` to `Unify.kt`**, beside `createAnd`, implementing the flattening rule. Process the conditions left to right as a worklist:

```
out = []; k = refs; rest = conds (and, for DrsImp, tail = consequent)
for each c in order:
    if c is Drs(j, cs):
        out   = out.map { qshift(it, j) }
        rest  = rest.map { qshift(it, j) }   // the not-yet-processed conditions
        tail  = qshift(tail, j)
        k    += j
        push cs onto the front of rest       // they keep their indices
    else out += c
```

Return `Drs(k, out)` or `DrsImp(k, out, tail)`.

VP[num=?n, sem=<?v(?obj)>] -> TV[num=?n, sem=<?v>] NP[sem=<?obj>]

  - **Names** (Angus, Irene, John, Mary, Suzie, Vincent, Mia, Marsellus, Fido, all `-loc`; Noosa `+loc`): `PropN[-loc, num=sg, sem=<\P.(([x], [Angus(x)]) + P(x))>] -> "Angus"`

  - **Determiners** (`num=sg` unless noted), each with its capitalized alternative:
